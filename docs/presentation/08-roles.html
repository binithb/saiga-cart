Roles & Flow

The human navigates: approves boundaries and reviews evidence before merge. The AI drives: drafts within those boundaries and runs checks. Add human checkpoints as risk and cost of reversal demand.

Aim → Map → Draft → Prove → Audit → Merge

From Aim to Merge

01 · Aim · Human

Approve the Boundaries

Choose the outcome, scope, safety constraints, and proof obligations.

Ready: unblocked, sized ≤ Medium, affected repos listed, acceptance criteria written; Definition of Ready | Done.

02 · Map · AI

Read Before Writing

Read repository instructions (AGENTS.md), docs/architecture.md, affected sibling repositories, and relevant ADRs. Surface conflicts or missing decisions for the human.

03 · Draft · AI

Keep Changes Reversible

Work on feature branches and draft PRs. Change only the agreed scope; update plans and architecture notes when boundaries change. Ask before exceeding the approved contract.

04 · Prove · AI

Run Automated Checks

Run the required tests and linters, fix failures, and record results against acceptance criteria. Passing checks are evidence, not human approval.

05 · Audit · Human

Judge the Evidence

Review contract conformance, the diff, and test evidence. Confirm passing checks, required architecture updates, and an approved PR summary before authorizing merge.

06 · Merge · Human-led

Land and Close the Loop

Merge only with human authorization. Then the delivery owner, assisted by AI, marks the local story Done and updates the linked tracker. Release approval remains a human responsibility.
