Two Operating Modes

AI-assisted engineering operates effectively at two distinct scales. Problems arise only when teams ask for Mode B results with Mode A tooling.

🎯
The governing rule: Context and verification must match the blast radius of the task. Local typing needs zero workspace overhead; cross-repo features require durable context.
Side-by-Side Comparison

Matching Method to Scope

Mode A

Typing Helper

Role: Autocomplete and localized snippet generator.

Context: Active open file and immediate clipboard.

Human Role: Acts as the system firewall and mental model holder.

Ideal For: Boilerplate, regexes, unit test scaffolding, single-file edits.

Mode B

System-Aware Partner

Role: Autonomous agent modifying contracts and implementations.

Context: Multi-root workspace, committed architecture, and active plans.

Human Role: Navigator setting goals, verifying evidence, and approving PRs.

Ideal For: Feature delivery, API refactors, multi-repo migrations, DoR audits.

Operational Matrix

When to Use Each Mode

Task Dimension Mode A: Helper Mode B: Partner
Scope of Change Single function / single file Multiple files / sibling repositories
Context Required Nearby syntax System architecture, ADRs, active plan
Verification Immediate visual check Automated test suite, pre-commit audit
Durable Artifacts None AGENTS.md, docs/planning/, docs/adr/
