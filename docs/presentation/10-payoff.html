Adopt in Four Steps

Start with one bounded delivery slice. Keep only the context that helps the next person or agent act correctly, then measure whether the practice earns its upkeep.

Start small

Build the Habit, Not a Bigger Wiki

01

Capture the System FAQ

Put recurring instructions and safety boundaries in AGENTS.md. Link to authoritative details rather than copying them.

02

Map the Architecture

Summarize repository ownership and contracts in docs/architecture.md. Record consequential choices in docs/adr/.

03

Version the Active Plan

Put a Ready story in docs/planning/, link its tracker issue, and define verification in docs/workflow.md. Review plan and code in the same PR.

04

Pilot, Measure, Prune

Run the Roles & Flow loop. Remove stale guidance and keep what reduces confusion without adding more maintenance than it saves.

Pilot Goals, Not ROI Promises

No measured ROI is established here. Before the pilot, agree targets and record a baseline on comparable tasks. Compare context setup minutes, review and repair time, and reopened decisions; include time spent maintaining docs. Aim to reduce that total without increasing escaped defects or missing customer outcomes.

Try It in Your Workspace

The bootstrapper creates the workspace structure and planning templates; your team supplies the real system context.
