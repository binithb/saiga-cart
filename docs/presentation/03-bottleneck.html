The Bottleneck Moved

AI can generate implementation faster than a human can determine whether a large diff belongs in the system. The scarce work is making intent precise enough to direct, constrain, and prove the change.

↗
Oversight moves upstream: begin review with the design contract, then use the implementation and its evidence to confirm that contract was met.
What Changed

The Control Point Moves Upstream

Before fast generationWith fast generation
Implementation time limits delivery.Unambiguous intent and reliable verification limit safe delivery.
Review discovers much of the design from the diff.Review begins with the design contract; the diff demonstrates conformance.
Code holds much of the team's implicit context.Constraints must be recorded so every human and agent session applies them consistently.

Specify What Must Be True, Then Let Implementation Be Fast

For a meaningful change, state the outcome, system boundary, important decisions, safety constraints, and evidence that proves success. An agent can draft quickly within those bounds; a human can judge the resulting work without reverse-engineering its intent.

Not a Bigger Wiki

The right specification is the smallest durable shared context that prevents important decisions from being guessed or forgotten. A local edit may need only a clear task and focused test; migrations, public interfaces, and cross-repository work need more.

Source: The bottleneck-shift framing is adapted from the Sputnik AI workspace presentation and Axel Molist's What 6 months of AI coding did to my dev team.
