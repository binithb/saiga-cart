Scaling AI in Real Software

AI coding models have made tremendous leaps in capability, but raw model power without a shared way of working creates friction. This guide explains how to turn AI capability into durable, cross-repository software engineering.

💡
The core insight: AI tools matured faster than our working methods. Ad hoc prompting works for small local tasks, but real projects require durable, committed context that survives across sessions and teammates.
The Core Capabilities

Two Capabilities Every AI Project Needs

01

Cross-Repo AI Context

Unified multi-root workspace where AI agents reason about contracts, shared schemas, and dependencies across sibling repositories in a single session.

  • Eliminates window switching and prompt re-pasting
  • Enforces cross-cutting architectural constraints
02

Durable Delivery Planning

Versioned markdown hierarchy (PIs, Sprints, Cycles, or Kanban) living directly beside the code with explicit Definition of Ready (DoR) gates.

  • Prevents settled decisions from being forgotten
  • Maintains 1:1 bidirectional links with issue trackers
