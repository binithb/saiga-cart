From Aim to Merge

How a feature flows safely through human-AI collaboration in six discrete, verifiable steps.

⚡
Single human gate: Rather than approving every single turn, the human approves once at the merge gate with full test verification and diff evidence in hand.
The 6-Step Loop

Lifecycle of a Workspace Change

01 · Aim

Human Sets Direction

Human selects a refined story with Definition of Ready | Done and size Small or Medium.

02 · Map

AI Reads In-Repo Context

AI loads AGENTS.md, architecture.md, sibling repos, and relevant ADRs before writing code.

03 · Draft

AI Builds on Branch

AI creates a feature branch and applies micro-surgical code changes across affected repositories.

04 · Prove

Targeted Verification

AI executes existing test suites and linters, iterating autonomously on errors until checks pass.

05 · Audit

Human Reviews Diff

Human inspects the concise PR summary card, code diff, and automated test pass evidence.

06 · Merge

Land & Update Plan

PR is merged to main. Local story is marked Done and synced with the remote issue tracker.

Definition of Ready (DoR) + Definition of Done (DoD)

DoR: Story is unblocked, sized ≤ Medium, affected repos listed, acceptance criteria written.
DoD: Tests pass, linters pass, architecture doc updated if boundaries changed, PR summary card approved.
