Four Artifacts

Reduce drift with four categories of durable context in git, not four literal files. Intent is a planning directory; decisions and evidence may span several files.

📁
The lightweight oversight contract: reality, intent, reasons, and evidence make clear what must be true before an agent implements. Nothing load-bearing should live only in chat scrollback or ephemeral memory.
The 4 Categories

What Earns a Place in the Repository

01 · Reality

What Is True Now

Current architecture, directory contracts, and repository ownership. Updated in the same PR that changes system structure.

Path: docs/architecture.md

02 · Intent

What We Are Building Next

The active delivery increment (PI, sprint, cycle, or milestone) with explicit acceptance criteria, story sizing, and DoR status.

Path: docs/planning/ (active increment, stories, and progress)

03 · Reasons

Why We Chose It

Append-only Architectural Decision Records (ADRs). Superseded rather than edited, preventing resolved debates from reopening.

Path: docs/adr/0001-*.md

04 · Evidence

What Counts as Done

Verification commands, pass/fail criteria, and recorded results. Tests show specified behavior; human review judges the change and its limits.

Paths: docs/workflow.md (DoD), tests, and PR evidence

Documentation Hygiene Rule

Keep context concise and current. Stale guidance can misdirect the next session. If a statement stops being true, update or remove it in the same PR; preserve decision history through superseding ADRs.
