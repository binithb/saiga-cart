The Practice · 5 / 9

Four Committed Files

To eliminate drift, replace chat memory with four small, plain-text categories committed directly in git beside the code. Together they form the lightweight oversight contract every session can apply.

📁
The lightweight oversight contract: reality, intent, reasons, and evidence make clear what must be true before an agent implements. Nothing load-bearing should live only in chat scrollback or ephemeral memory.
The 4 Categories

What Earns a Place in the Repository

01 · Reality

What Is True Now

Current architecture, directory contracts, and repository ownership. Updated in the same PR that changes system structure.

Canonical file: docs/architecture.md

02 · Intent

What We Are Building Next

The active delivery increment (PI, sprint, cycle, or milestone) with explicit acceptance criteria, story sizing, and DoR status.

Canonical file: docs/planning/01/

03 · Reasons

Why We Chose It

Append-only Architectural Decision Records (ADRs). Superseded rather than edited, preventing resolved debates from reopening.

Canonical file: docs/adr/0001-*.md

04 · Evidence

What Counts as Done

Executable verification commands and pass/fail criteria. "The agent says it works" is not verification — only test commands prove it.

Canonical file: docs/workflow.md (DoD)

Documentation Hygiene Rule

Keep files concise and single-purpose. Stale documentation actively degrades AI reasoning by injecting hallucinations. If a statement stops being true, update or delete it in the same PR.
